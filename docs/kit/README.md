# PULSE — Complete Project Kit (PDFs + Markdown only)

NASA Space Apps Challenge 2026 — "Create Health Monitoring Software for Astronauts on Space Missions"

**This archive intentionally contains NO HTML files.** The running website is generated on YOUR machine by the
Z.ai desktop app from the paste-ready prompts in the Build Playbook — that is the documented build method, and
it keeps this kit compliant with "documents only" rules. Every build is therefore fresh, auditable, and yours.

**Citation round (14 November 2026):** the challenge page's five official resources — NASA HRP's 5 Hazards,
Risks, and Ongoing Research + the CSA's radiation-monitoring and space-science pages — were fetched, read and
integrated into every file of this kit. They are sources 21–25 in `SOURCES.md`, mapped landing-place by
landing-place in the dossier (§5), seeded into the app's source panel (14 → 19 entries via Playbook prompt P7),
named in the video script and its citation wall, and cross-checked against the official 25-point judging rubric
in the Evaluation PDF. Two new PDFs cover the official 30-second demo format and the project-page References
field.

## Quick start (first 15 minutes)

1. Read `PULSE_Kit_User_Guide.pdf` sections 1–2 (the map and the master procedure).
2. Skim `PULSE_NASA_Research_Dossier.pdf` sections 2–3 and 5 (the challenge statement, what NASA already has, and where each of the five official resources lives in the project).
3. Open the Z.ai desktop app, start a new conversation, and paste Prompt P0 from the Build Playbook (§3).

## Verification in one line

The build "works" when 12 specific checks pass with zero console errors — every check has an explicit pass
condition in the User Guide §4, including: BLIND quality gate refuses bad data, every engine output receipts,
threshold edits are receipted, LOS queues escalations (QUEUED-FS) and AOS flushes them with sync receipts, and
the judge tour completes unattended.

## Citations
